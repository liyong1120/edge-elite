## 一、重新生成武器（主路径：Blender 参数化建模）

**为什么用这条路而不是 AI 文生 3D**：规格书要求面数 ≤300~700、枪口朝 −Z、
原点在握把、材质按 `mat_xxx_yyy` 命名。AI 生成器面数下限是 10000，
且朝向/原点/材质命名都不可控；Blender 脚本建模这四项全部精确可控。

### 生成命令

```bash
cd D:/cpan/Desktop/cs/cs-godot

# 全部 17 把（覆盖已有）
"/d/Program Files/Blender Foundation/Blender 5.2/blender.exe" \
  --background --factory-startup --python tools/build_weapons.py -- \
  --all --out "D:/cpan/Desktop/cs/cs-godot/models/fpv"

# 只做指定的几把
... --python tools/build_weapons.py -- --only AK47 AWP --out models/fpv

# 不传 --all / --only 时，只补 models/fpv 里缺失的
... --python tools/build_weapons.py -- --out models/fpv
```

单个模型 1~2 秒，17 把总共约 30 秒。**不消耗任何云端额度。**

### 改一把枪的外形

打开 `tools/build_weapons.py`，找到对应的 `w_xxx()` 函数。
每个部件就是一行元组，坐标系是：

```
X = 左右（宽度）    Y = 枪长（枪口朝 +Y）    Z = 上下
```

两种构件：

```python
("box", (宽, 长, 高), (x, y, z), (绕X°, 绕Y°, 绕Z°), "材质key")
("cyl", 半径, 长度,   (x, y, z), (绕X°, 绕Y°, 绕Z°), 分段数, "材质key")
```

圆柱默认轴向是 Z，所以**枪管沿 Y 轴要写 `(90, 0, 0)`**。
改完直接重跑生成命令即可。

### 改材质

`tools/build_weapons.py` 顶部的 `MATLIB`：

```python
"metal_dark": ((0.070, 0.070, 0.080), 0.90, 0.42),
#             (R, G, B 基色)          金属度  粗糙度
```

材质会自动按 `mat_{型号}_{key}` 命名，例如 `mat_ak47_wood`。

### 改完一定要自检

```bash
python tools/glb_check.py
```

## 三之二、尺寸归一化（AI 生成素材的必备后处理）

AI（无论文生 3D 还是图生 3D）吐出来的模型尺寸是随机的 ——
实测见过 2.43 米长的 AK47、2.80 米长的 AWP。提示词里写比例只能「引导」，
**尺寸的精确保证只能靠这一步**。

```bash
# 批量处理一个目录（按文件名自动查规格表）
"/d/Program Files/Blender Foundation/Blender 5.2/blender.exe" \
  --background --factory-startup --python tools/normalize_glb.py -- \
  --in-dir "D:/下载/武器" --out-dir "D:/cpan/Desktop/cs/cs-godot/models/fpv"

# 单个文件 + 顺便减面到 600 面
... --python tools/normalize_glb.py -- \
  --in "D:/下载/AK47_raw.glb" --out "models/fpv/AK47.glb" --decimate 600
```

它做的事：测包围盒 → 最长边缩放到规格全长（保持比例不变形）→
最长轴对齐 Z → 居中到原点 → 可选 Decimate 减面 → 导出单位变换的干净 GLB。

**实测**：2.43m 的 AK47 → 0.88m；2.80m 的 AWP → 1.14m；
20594 面的角色减到 2999 面，15 张贴图完整保留。

### ⚠️ 带骨骼的模型会被跳过（这是有意的）

顶点级缩放会把**蒙皮和动画整段抹掉** —— 实测角色 52 个动画会全部丢失，
游戏里角色就废了。所以脚本默认跳过带骨骼的模型并打印提示。

角色确实要缩放时加 `--allow-rig`，此时只对骨架做等比缩放、不碰顶点、不减面。
实测 `--allow-rig` 能完整保住：蒙皮 1 个 / 动画 52 个 / 骨骼权重 / 15 张贴图。

常用开关：

| 参数 | 作用 |
|------|------|
| `--in` / `--out` | 单个文件输入输出 |
| `--in-dir` / `--out-dir` | 目录批量 |
| `--decimate N` | 减面到 N 三角面 |
| `--len X` | 手动指定目标长度（米），用于规格表外的型号 |
| `--dry-run` | 只预览不写文件 |
| `--allow-rig` | 允许处理带骨骼模型（仅等比缩放骨架） |

## 四、原规格书需要纠正的 3 点

### 纠正 1：「枪口朝 −Z」「原点在握把位置」现在已由脚本保证

`build_weapons.py` 导出前做了两件事：

1. `transform_apply` 把 join 残留的变换烘进网格，保证导出节点是**单位变换**
   （不这么做的话，Godot 里再旋转会出现斜切）
2. 顶点整体平移 `-grip_pos`，让**握把位于原点 (0,0,0)**

而 Blender 导出 glTF 时 +Y 自动映射为 −Z，所以**枪口天然朝 −Z**。

另外 `scripts/player.gd:1472` 的 `_fit_viewmodel()` 还有一层兜底：
忽略 glb 根变换 → 测包围盒 → 最长轴转到 −Z → 缩放到 0.73m → 居中。
**所以即使模型是歪的、尺寸错的，游戏里也能正常显示。**

⚠️ 唯一风险：代码按「最长轴 = 枪管方向」判朝向。
AWP / G3SG1 / SG550 这类大瞄准镜狙击枪，若竖直方向超过枪身长度会被转成竖的。
当前模型实测都是长边 Z，没问题。

### 纠正 2：不用删 `.godot/imported/`

正确做法：Godot 里 `Project → Reload Current Project`，编辑器会自动重新导入。
或者只删对应的 `.glb.import` 文件。

新放入 `models/fpv/` 的 GLB 会自动生成 `.import`，
代码里 `_load_fpv_model()` 用 `ResourceLoader.exists()` 判断，**放入即生效，无需改代码**。

### 纠正 3：面数指标现在达标了

规格书要求武器 ≤300~700 面，实际生成 88~380 面，**全部达标**。
（这是 AI 生成做不到、而脚本建模能做到的事。）

## 五、验收流程

```bash
cd D:/cpan/Desktop/cs/cs-godot
python tools/glb_check.py
```

标记含义：
- `✓` 符合规格
- `!` 与规格有偏差但游戏能跑
- `-` 仅提示（如角色面数超 3000，属正常）
- `×` 不可用，必须重做

**脚本判不出、必须进游戏肉眼看的**：
- [ ] 狙击枪没有被转成竖的
- [ ] 枪的比例像枪
- [ ] 颜色符合经典战术射击风格，无霓虹/发光
- [ ] 第一人称视角没有多余的手/手臂挡画面
- [ ] Godot 控制台无红色报错

### 进游戏前

替换了模型文件后，**删掉旧的 `.glb.import`**（已做），
再在 Godot 里 `Project → Reload Current Project`。

## 六、常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 放进去了游戏里没变 | Godot 没重新扫描 | `Project → Reload Current Project` |
| 枪在手里是竖着的 | 瞄准镜导致最长轴判定错误 | 改 `w_xxx()` 压低瞄准镜，重跑 |
| 枪太大/太小 | 正常 | 代码自动缩放到 0.73m，不用管 |
| 模型在 Godot 里被斜切 | 导出节点带了非均匀缩放 | 确认 `build_weapons.py` 里的 `transform_apply` 没被删 |
| 模型发黑 | 金属度高但场景无环境反射 | 项目有 WorldEnvironment + 程序化天空，正常不会黑 |
| 面数超标 | 部件加太多 | 减圆柱分段数（10→8），或删装饰件 |
| 生成脚本报找不到 GLB | 路径不对 | `--out` 用绝对路径 |
